# Валидация анализа ДНК денег

## ⛔ КРИТИЧЕСКОЕ ПРАВИЛО

**Валидация = ОТДЕЛЬНЫЙ subagent через Task tool.** НЕ самопроверка автора текста. Subagent читает текст без контекста создания — это устраняет bias.

## INPUT-гейт

- [ ] `<Имя>_<DDMMYYYY>_ДНК_денег.md` существует
- [ ] `karta_*.csv` существует (для сверки)

## Чек-лист (проверять КАЖДЫЙ пункт)

### 1. Все 8 финансовых точек описаны (HARD FAIL)

Проверить наличие разделов для каждой из 8 точек:
1. Асцендент
2. Юпитер
3. Сатурн
4. 2-й дом
5. 11-й дом
6. Раху/Кету
7. Солнце
8. Луна

**Fail если:** хотя бы одна точка не описана.

### 2. Каждая планета = знак + дом + контекст (HARD FAIL)

Для каждой описанной планеты проверить:
- Указан дом, в котором стоит
- Указан знак
- Дано объяснение, про что этот дом простым языком
- Если нет цивилизации — контекст знака и дома всё равно описан

**Fail если:** планета описана без дома или без знака.

### 3. Луна — полный анализ (HARD FAIL)

- ВСЕ джйотиш-аспекты от других планет указаны
- Соединение с Кету/Раху (если есть) описано
- Каждый аспект связан с деньгами, не просто «аспектирует»

**Fail если:** анализ Луны выборочный (пропущены аспекты, видные в CSV).

### 4. Раху/Кету — диспозиторы (HARD FAIL)

- Для Раху указан диспозитор (хозяин ЗНАКА)
- Для Кету указан диспозитор (хозяин ЗНАКА)
- Диспозитор описан: дом, знак, связь с деньгами

**Fail если:** диспозиторы не указаны или указан хозяин накшатры вместо знака.

### 5. Планетные соединения (HARD FAIL)

Проверить по CSV: если две планеты стоят в одном доме — описано ли их взаимодействие.

**Fail если:** соединения планет в одном доме не описаны.

### 6. Асцендент — память прошлых жизней

Если на Асценденте ☌ со звездой/цивилизацией с орбом <1°:
- Описана память прошлого воплощения
- Описан механизм материализации денег через эту цивилизацию

**Fail если:** тугое соединение на Асценденте без описания памяти и материализации.

### 7. 11 сфер максимальных денег (HARD FAIL)

- Ровно 11 сфер
- 3 эзотерические + 3 материальные + 4 масштабного бизнеса + 1 интеграционная
- Каждая привязана к конкретным положениям ЭТОГО клиента
- Нет generic-формулировок

**Fail если:** <11 или >11, или шаблонные формулировки, или нет привязки к карте.

### 8. 5 сил + 5 теней (HARD FAIL)

- Ровно 5 сил и ровно 5 теней
- Формат таблицы (два столбца рядом)
- Уникальные, не шаблонные

**Fail если:** не 5+5, или нет формата таблицы.

### 9. Помощник в деньгах (HARD FAIL)

- Раздел «Помощник в деньгах» присутствует
- Описан тип партнёра на основании карты
- 2-3 предложения

**Fail если:** раздел отсутствует.

### 10. Возрасты финансового прорыва

- Таблица с годами/возрастами
- Прошлые (с 22 лет) + будущие
- Привязаны к накшатрам финансовых позиций

**Fail если:** таблица отсутствует или содержит только будущие/только прошлые.

### 11. Практики

- Ровно 2 практики: материализация + выход из тени
- Каждая уникальна для данного клиента

**Fail если:** <2 или >2 практик.

### 12. Ссылки на услуги

- Ровно 3 ссылки: энергодуш, консультация, сопровождение
- Каждая ровно 1 раз
- Каждая оформлена как гиперссылка
- Равномерно разнесены (между ссылками ≥40 строк)

**Fail если:** <3 ссылок, или ссылки без гиперссылки, или все в одном месте.

### 13. Терминология

- [ ] Нет «бесплатно»
- [ ] Нет «пад», «навамша»
- [ ] 6-й дом ≠ «кризис» (кризис = 8-й; 6-й = конфликт, трудоголизм)
- [ ] Автор = «Кайя Каэн» (НЕ «Дарья Лачинова»)
- [ ] Нет «Школа Полной Луны»
- [ ] Дома объяснены простым языком (не «8-й дом» без расшифровки)

### 14. Обращение — только «вы/вас/ваш»

Сканировать текст: не должно быть «она», «у неё», «он», «у него», «человек».

**Fail если:** используется третье лицо.

### 15. Аспекты верифицированы по CSV

Каждый упомянутый аспект (цивилизационный) ОБЯЗАН присутствовать в CSV-файле клиента.

**HARD FAIL если:** аспект выдуман.

### 16. Книга как гиперссылка

Книга «Активация Внеземной ДНК» упоминается ТОЛЬКО как `[«Активация Внеземной ДНК»](https://intergalactic-astrology.com/book/)`.

**Fail если:** книга без гиперссылки.

## OUTPUT-гейт

Запись в лог клиента `DariaGalactic/Правила/Логи/<клиент>.md`:
- Результат: `OK | FAIL_iter1 | FAIL_iter2`
- Конкретный список замечаний

## Правило двух итераций

Если FAIL iter 1 — текст возвращается автору с замечаниями. Автор исправляет. Валидатор проверяет повторно.

Если FAIL iter 2 — эскалация Дарье с обоими списками замечаний.

## Формат ответа

```
## РЕЗУЛЬТАТ ВАЛИДАЦИИ ДНК ДЕНЕГ

Статус: OK / FAIL

### Пройдено:
- [x] Пункт 1: ...
...

### Не пройдено:
- [ ] Пункт N: [описание проблемы + что именно исправить]

### Замечания (не блокирующие):
- [мелкие улучшения]
```
