# Доставка разборов миссии — инструкция для Дарьи

Документ показывает:
1. как клиент попадает в таблицу с уже готовыми данными рождения,
2. как ты делаешь свой разбор по этим данным,
3. как одной командой выдать клиенту PDF и закрыть строку.

> **Перед запуском**: см. раздел «Что НЕ делать» в конце документа —
> были инциденты, когда отправили чужой разбор не тому клиенту.
> Скрипт теперь блокирует такое поведение, но прочитать всё равно надо.

## 1. Где смотреть всё (одна Google-таблица)

Единая Google-таблица «Учёт покупок и разборов» в папке **Разборы**:

[Открыть лист](https://docs.google.com/spreadsheets/d/1X2voXTHnywDHXk1BRVNsYktrL8MtXHqxl6jhwymLzWE/edit)

Колонки (текущая схема, после правок мая 2026):

| Кол | Что | Кто заполняет |
|---|---|---|
| A | Дата покупки | автомат |
| B | Email | автомат |
| C | Имя клиента | клиент при заполнении формы |
| D | Продукт | автомат |
| E | Сумма | автомат |
| F | Контракт ID | автомат |
| G | **Статус** | автомат / `deliver_mission.py` |
| H | Дата рождения | клиент при заполнении формы |
| I | Время рождения | клиент при заполнении формы |
| J | Город рождения | клиент при заполнении формы |
| K | Координаты | клиент (автокомплит города) |
| L | Часовой пояс | клиент (автокомплит города) |
| M | **Ссылка на PDF разбора** | `deliver_mission.py` |
| N | **Дата выдачи** | `deliver_mission.py` |
| O | **Папка клиента в Drive** | Worker (после оплаты) / `deliver_mission.py` |
| P | **Телефон (WhatsApp)** | клиент при заполнении формы (поле обязательное) |

Возможные статусы (G):

- `Лид` — клиент заполнил форму, ещё не оплатил. У него уже есть `Контракт ID`,
  но ждём `payment.success`.
- `Готовится ссылка на оплату` / `Ссылка на оплату отправлена` /
  `Оплата временно недоступна · повторяем` — служебные статусы цикла
  повторной выдачи ссылки (если LavaTop не сразу сгенерил инвойс).
- `В разборе у Дарьи` — оплата прошла, можно работать. **Это твоя очередь.**
- `Готов · выдан клиенту` — разбор выкатан в кабинет, клиенту автоматически
  ушло письмо «Ваш разбор готов».
- `Выдано автоматически` — товары без ручной выдачи (книга и т.п.).
- `Ошибка / возврат` — выставляется руками, если что-то пошло не так.

## 2. Что происходит до тебя — без твоего участия

1. Клиент на `intergalactic-astrology.com/about.html` жмёт «Заказать анализ за 37 €».
2. В модалке заполняет: имя, email, дату/время/город рождения. Клик «Перейти к оплате».
3. Worker сразу:
   - кладёт строку в лист со статусом `Лид`,
   - выписывает в LavaTop персональный счёт,
   - редиректит клиента на оплату.
4. Клиент платит. LavaTop стучит вебхуком к нам:
   - **та же строка** обновляется: статус → `В разборе у Дарьи`, появляется
     сумма (E) и контракт (F), данные рождения (H–L) уже там, телефон в P,
   - на почту клиенту улетает письмо «Доступ в личный кабинет», в кабинете
     карточка миссии с надписью «Анализ создан, проверяется»,
   - в WhatsApp клиенту приходит дубль ссылки на кабинет (если телефон
     указан в форме — а это поле обязательное с мая 2026).

В этот момент в таблице у тебя появляется строка с зелёной зоной (H–L
заполнены, G = `В разборе у Дарьи`) — пора делать разбор.

## 3. Как ты выдаёшь готовый разбор

Скрипт работает в двух режимах:
- **Полный (рекомендуется):** на вход даёшь *папку клиента* — внутри
  лежат PDF, обложка `Generated_image.png` и `summary.md`. Кабинет
  показывает inline-превью (обложка + ключевые тезисы + кнопка
  «Скачать полный PDF»).
- **Legacy:** на вход только PDF, без обложки и summary. В кабинете
  будет только золотая кнопка «Открыть разбор → PDF».

### 3.1. Возьми данные из строки

Колонки H, I, J, K, L — это всё, что нужно для построения карты:

| H | I | J | K | L |
|---|---|---|---|---|
| 20.06.1990 | 14:30 | Москва, г. Москва, Россия | 55.7558, 37.6173 | Europe/Moscow |

Готовая натальная карта в формате CSV для калькулятора уже лежит в
папке клиента на Drive (колонка O в листе) под именем
`karta_<short>.csv` — Worker положил её туда автоматически сразу после
оплаты. Чтобы синхронизировать папку локально, запусти:

```bash
python3 scripts/pull_client.py клиент@example.com
```

Если CSV в папке вдруг нет (мобильный браузер клиента не дотянул) —
скрипт сам перегенерирует и положит карту. Запасной ручной режим:
`pull_client.py --regen-csv-for клиент@example.com`.

### 3.2. Сделай разбор, сложи всё в одну папку

В папке клиента (`D:\DariaGalactic\Профайлы клиентов\<Имя>_<contract12>_<YYYYMMDD>\`):

- `*_миссия.pdf` — полный разбор,
- `Generated_image.png` — обложка-визуализация в полном размере,
- `summary.md` — выжимка по правилу из методички.

Имена файлов произвольные — скрипт сам найдёт нужное по расширению и
шаблону имени.

### 3.3. Одна команда в терминале

```bash
cd "/Users/<твой_логин>/Desktop/Producty/4_Intergalactic/intergalacticAstoAgent"
python3 scripts/deliver_mission.py клиент@example.com \
    "D:\\DariaGalactic\\Профайлы клиентов\\Имя_5e42_20260510"
```

(Если папки нет — можно передать просто `*.pdf`, тогда сработает
legacy-режим без обложки/summary.)

**Скрипт перед отправкой выведет блок «ПРОВЕРКА КЛИЕНТА» и попросит
ответить `yes`.** Это страховка от инцидентов «отправили не тому
клиенту». Если в Sheet не нашлась строка с этим email — скрипт
остановится и не пошлёт ничего. Если email в Sheet не совпадает с
переданным аргументом — тоже остановится. Только при совпадении и
твоём `yes` начнёт загрузку.

Что делает скрипт по шагам:

1. Лукап строки клиента в Google Sheet (контрактID, имя, дата покупки,
   телефон из col P).
2. **Показывает блок «ПРОВЕРКА КЛИЕНТА»** и ждёт `yes`.
3. Папка клиента в Drive «Разборы» — Worker уже создал её после
   оплаты, скрипт находит и переиспользует. Если её нет (старые
   клиенты) — создаёт сам и пишет URL в колонку O листа.
4. Загружает PDF в эту папку под именем `mission_<email>_<timestamp>.pdf`.
5. Загружает полную обложку `mission_<email>_<timestamp>_cover.png`.
6. Парсит `summary.md` → HTML, сжимает обложку в WebP для кабинета.
7. Кладёт `cover.webp` и `summary.html` в Cloudflare R2 (это то, что
   видит клиент внутри карточки кабинета).
8. Дёргает Worker `/admin/mission`. Worker:
   - переводит миссию в статус `ready` в KV;
   - обновляет лист: G → `Готов · выдан клиенту`, M → ссылка на PDF,
     N → дата выдачи;
   - **отправляет клиенту письмо** «Ваш разбор готов» через Resend
     (от `info@…`) с кнопкой «Открыть кабинет» и ссылкой на WhatsApp
     для вопросов;
   - **отправляет WhatsApp** «Анализ миссии готов» через Green API
     (если в col P есть телефон).

Все каналы идемпотентны: повторный запуск скрипта с тем же email при
уже выкатанной миссии не пошлёт ни email, ни WhatsApp дважды (защита
по `previousStatus === 'ready'`).

Через ~30 секунд клиент видит результат в кабинете, получает письмо и
сообщение в WhatsApp. Финальный вывод скрипта подтверждает каналы:
```
   ✓ Письмо «разбор готов» отправлено клиенту.
   ✓ WhatsApp «разбор готов» отправлено клиенту.
```

## 4. Один раз: настройка машины

Все доступы лежат в одной папке `DariaGalactic/config/` внутри агентского
проекта. Эта папка в `.gitignore` — наружу не уходит.

```
intergalacticAstoAgent/DariaGalactic/config/
├── client_secret_*.json     ← OAuth ключ Google (выдаёт Кирилл)
├── .env                     ← WORKER_URL, ADMIN_SECRET, GDRIVE_FOLDER_ID
├── secrets.local.md         ← мастер-копия всех ключей
├── gdrive_token.json        ← создаётся автоматически после первого запуска
└── cabinet_sheet_token.json ← создаётся автоматически после первого запуска
```

Если что-то отсутствует — открой `secrets.local.md` (там есть всё для
восстановления) или попроси Кирилла прислать `client_secret_*.json`.

### Зависимости (один раз)

```bash
python3 -m pip install --upgrade google-api-python-client google-auth-httplib2 \
    google-auth-oauthlib requests python-dotenv
```

При самом первом запуске откроется окно браузера с просьбой разрешить
доступ к Drive — нажми «Разрешить». Дальше скрипт работает молча.

## 5. Что делать, если…

**Клиент пишет «не приходит письмо»** — попроси проверить «Спам».
Письмо отправляется с `info@intergalacticastrology.com` через Resend.
Если в спаме тоже нет — открой
`https://intergalactic-cabinet.duduk12250405.workers.dev/admin/webhook-log`
с заголовком `X-Admin-Key` (значение в `secrets.local.md`) и проверь,
ловил ли вообще Worker оплату. Если не ловил — пиши Кириллу.

**Клиент пишет «оплатил, в кабинете пусто»** — открой таблицу, найди его
email. Если строки нет — webhook от LavaTop не дошёл, пиши Кириллу.
Если строка есть, статус `Лид` — оплата не дошла либо ещё в очереди.
Подожди 5 минут (Worker раз в 5 минут добирает пропущенные оплаты через
LavaTop API). Если статус не меняется — пиши Кириллу.

**Скрипт ругается «admin auth failed» / 401** — значение `ADMIN_SECRET`
в `.env` не совпадает с тем, что в Cloudflare. Возьми актуальный из
`intergalacticAstoAgent/DariaGalactic/config/secrets.local.md`.

**Скрипт упал на загрузке в Drive** — проверь, что файл существует,
интернет работает, и `gdrive_token.json` не повреждён (можно удалить и
переавторизоваться заново — браузер откроется автоматически).

**Хочешь руками поменять статус** — открой таблицу и измени колонку G.
Worker таблицу не перезатирает, он только дополняет.

**Хочешь сбросить тестовую запись клиента** — попроси Кирилла прогнать
`POST /admin/reset-email` (удаляет из KV `sales:`, `mission:`, `lead:`
и индекс `lead-contract:*`). Строку из листа после этого можно удалить
вручную.

**Хочешь дослать письмо «разбор готов»** (для клиентов, выкатанных до
11 мая 2026 — в системе тогда не было автоматической отправки) —
повторно запусти `deliver_mission.py` с той же папкой. Если миссия
уже в статусе `ready`, обычное письмо не уйдёт (защита от дублей).
Чтобы принудительно отправить, попроси Кирилла дёрнуть Worker:

```bash
curl -X POST https://cabinet.intergalactic-astrology.com/admin/mission \
  -H "X-Admin-Key: $ADMIN_SECRET" -H "Content-Type: application/json" \
  -d '{"email":"клиент@example.com","status":"ready",
       "driveLink":"<текущая ссылка на PDF>","notifyEmail":true}'
```

Флаг `notifyEmail:true` заставляет воркер отправить письмо даже если
статус уже `ready` (без него защита от дублей пропустит).

## 6. Что НЕ делать (на основе реальных инцидентов)

В мае 2026 было четыре инцидента, в которых разбор уходил не тому
клиенту. Каждый из них теперь блокируется кодом, но правило для
оператора остаётся:

> **Email клиента берётся ТОЛЬКО из Google Sheet.** Не «из памяти»,
> не «по похожему имени из чата», не «как у предыдущего клиента».
> Только из строки в листе «Учёт покупок и разборов».

Что произошло и что теперь невозможно сделать:

| # | Что сделали (нельзя) | Почему так нельзя | Как код блокирует сейчас |
|---|---|---|---|
| 1 | Отправили разбор Омеру **без явного разрешения Дарьи** | Это её клиент, её решение когда выдавать | Скрипт спрашивает интерактивное `yes` перед отправкой. `--yes` использовать только когда оператор гарантированно сверил |
| 2 | Отправили Алину на `mamytka@gmail.com` (этого email вообще нет в Sheet) | Email взяли «из памяти», скрипт показал «Sheet match: НЕ НАЙДЕНО», оператор проигнорировал | Скрипт теперь жёстко падает с ошибкой `СТОП: для этого email нет строки «Анализ миссии…» в Sheet`, отправка не идёт |
| 3 | Отправили Марину на email Галины (`red-poppy-96@mail.ru`) | Email из похожего соседнего клиента | Скрипт сравнивает переданный email с email из Sheet. При несовпадении — `СТОП: email в Sheet не совпадает с переданным аргументом` |
| 4 | Файл Марины перезаписал файл Галины в её кабинете | Worker обновил одну и ту же mission-запись | Кабинет хранит миссии как массив `missions:<email>`, новая миссия добавляется отдельной записью с уникальным `contractId`. Перезаписать чужой PDF одним email больше нельзя без явного указания `contractId` |

Дополнительные правила оператора:

- **Файл из папки клиента ≠ имя в Sheet** — сравнивай **email** и
  **дату рождения** в выводе скрипта. Если хоть что-то не сходится —
  отменяй (`no`) и иди разбираться руками.
- **Не используй `--yes`** в обычной работе. Этот флаг для
  скриптовой автоматизации с заранее проверенными данными.
- **Если клиент жалуется «получил чужой разбор»** — НЕ исправляй
  «по горячим следам». Сначала открой кабинет клиента по magic-link,
  убедись какие именно missions там лежат, и только потом действуй.
  В случае массовой путаницы — пиши Кириллу.

## 7. Quick reference для агента-оператора (Cursor/Codex)

Если ты — субагент, который запускает `deliver_mission.py` от имени
Дарьи, действуй строго по этому чек-листу:

1. **Сначала — разрешение Дарьи.** Если в чате нет явного «отправь Х»
   (с указанием email) — НЕ запускай скрипт.
2. **Email — только из Sheet** (`sheets get values A:P`), не из имени
   папки клиента, не из истории чата, не «похожий».
3. Запускай **без `--yes`**: скрипт покажет блок «ПРОВЕРКА КЛИЕНТА»,
   ты должен сверить email + имя + дату рождения + contractId с тем,
   что Дарья просила, и только тогда ответить `yes`.
4. Если скрипт упал на «СТОП…» — НЕ обходи проверку, сообщай Кириллу.
5. После отправки — приложи в чат финальный вывод скрипта (строки про
   Sheet update, Email, WhatsApp), чтобы Дарья видела факт доставки.

## 8. Технические детали (если интересно)

- Worker'у никакая база не нужна. Он использует Cloudflare KV для
  быстрого чтения покупок (когда клиент входит в кабинет) и пишет
  параллельно в Google Sheet (для тебя).
- KV видеть необязательно. Если когда-нибудь понадобится:
  Cloudflare → Storage & Databases → KV → namespace `cabinet_sales`. Ключи:
  - `sales:<email>` — массив покупок этого клиента;
  - `mission:<email>` — текущий статус разбора (birth, driveLink, deliveredAt);
  - `lead:<email>` — данные формы до оплаты (удаляется после `payment.success`);
  - `lead-contract:<contractId>` → email — индекс для слияния лида с оплатой;
  - `webhook:log` — последние 30 событий от LavaTop, для дебага.
- Все секреты — в Cloudflare Worker → Settings → Variables and Secrets,
  и в `intergalacticAstoAgent/DariaGalactic/config/secrets.local.md` локально.
