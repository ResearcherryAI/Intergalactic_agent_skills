# Спецификация TIER-калькулятора (v3.3, 27.05.2026)

Спецификация описывает логику детерминированного расчёта Top-3 цивилизаций из
натальной карты, эксперимент по выбору правил приоритизации и протокол валидации.
Документ — рабочий стандарт для всех последующих калибровок калькулятора.

Исходный код: `code/tier_calculator.py`.
Симулятор экспериментов: `code/simulate_tier_rules.py`.
Скрипт сравнения с эталонами Дарьи: `code/compare_batch2_vs_reference.py`.

---

## 1. Назначение

TIER-калькулятор принимает CSV натальной карты (формат `karta_<hash>.csv`) и
возвращает структуру для последующей подачи в LLM-промпт:

- **Top-3 цивилизаций** в порядке убывания приоритета.
- **Косвенные цивилизации** (orb 2-5° personal, 5-10° outer) — отдельным блоком
  с пометкой «косвенное влияние».
- **Nodes-only цивилизации** — отдельный список (направление эволюции, Раху/Кету).
- **Ascendant data** — знак, Лагнеша, накшатра/пада — детерминированно по градусу.
- **Soul age** — древняя (≥ 5 main-соединений) / средняя (3-4) / молодая (≤ 2).

Цель: исключить «творческую интерпретацию» астрологии моделью на этапе
структуры — оставить ей только нарратив.

---

## 2. Формула расчёта веса (одно соединение)

Для каждой пары `(планета, звезда, орб)` функция `tier_weight()` возвращает
вес, имя TIER-а и категорию (`main` / `indirect` / `out`):

### 2.1. Outer-планеты (Уран / Нептун / Плутон)

| Орб | TIER | Вес | Категория |
|---|---|---|---|
| < 1.0° | `TIER0_tight` | 3.0 | main |
| 1.0° - 5.0° | `TIER0_wide` | 3.0 | main |
| 5.0° - 10.0° | `TIER0_indirect` | 1.0 | indirect |
| ≥ 10.0° | OUT | 0 | out |

### 2.2. Personal-планеты (Солнце / Луна / Меркурий / Венера / Марс) и узлы (Раху / Кету)

| Орб | TIER | Вес | Категория |
|---|---|---|---|
| < 0.2° | `TIER1` | 3.0 | main |
| 0.2° - 1.0° | `TIER2` | 2.0 | main |
| 1.0° - 2.0° | `TIER3` | 1.5 | main |
| 2.0° - 5.0° | `TIER_indirect` | 0.5 | indirect |
| ≥ 5.0° | OUT | 0 | out |

### 2.3. GC-boost (Великий Аттрактор, Аттрактор Шепли, Галактический Центр)

Если звезда — одна из GC-точек, TIER повышается на одну ступень:

- `TIER3 + GC` → `TIER2+GC` (вес 2.0)
- `TIER2 + GC` → `TIER1+GC` (вес 3.0)
- `TIER1`, `TIER0_*` — остаются (уже максимум)

### 2.4. Группировка по цивилизациям

Несколько звёзд одного созвездия (Дифда + Тау Кита → Кит, Хадар + Проксима +
Толлиман → Центавр) объединяются в **одну цивилизацию** через `normalize_civ_name()`.
Веса всех соединений в этой цивилизации **суммируются** в поле `weight`.

GC-точки рассматриваются как самостоятельные цивилизации
(не объединяются с созвездиями).

## 3. Группы приоритета (v3.2)

Каждой цивилизации присваивается priority_group и group_rank. Сортировка Top-3
идёт по ключу `(group_rank ↑, weight ↓, min_orb ↑)`.

| Группа | rank | Когда срабатывает |
|---|---|---|
| **A1** | 0 | multi-contact non-node с TIER0_tight/TIER1 **ИЛИ** weight ≥ 5.0 (R7.1) |
| **A_gc_tight** | 1 | single conjunction с GC-точкой + узкий орб (outer<1°, personal<0.2°) |
| **A_personal_t1** | 2 | single personal TIER1 non-GC (orb<0.2°) |
| **A1_multi_personal_mid** | 2.5 | R7.2: ≥ 2 уникальных звезды одной цивилизации в орбе < 1° любыми планетами (хотя бы одна не узел) |
| **A_outer_tight** | 3 | single outer TIER0 узкий non-GC (orb<1°) |
| **A_nodes_multi** | 4 | multi-contact только через узлы (Раху/Кету) |
| **A_personal_node_trail** | 4.5 | R8: точная personal-линия orb<1° плюс узловой шлейф 2°-3° той же цивилизации |
| **A_gc_wide** | 5 | single conjunction с GC-точкой + широкий орб |
| **A1_low** | 6 | multi-contact non-node без TIER0_tight и TIER1 (TIER2/3/wide) |
| **B** | 7 | single outer TIER0 широкий non-GC |
| **C** | 8 | single personal TIER2 non-GC (orb<1°) |
| **D** | 9 | слабые: single TIER3 / nodes single |

Подробное обоснование R7 — в разделе «Эксперимент».

## 4. Что такое R7 (правило v3.2)

Цивилизация поднимается в Top если выполнено **любое** из двух условий:

### R7.1 — высокий суммарный вес

```python
if not only_nodes and c["weight"] >= 5.0:
    return "A1"
```

**Что ловит**: цивилизация имеет большую суммарную «массу» — много контактов
или один очень тугой. Пример: Центавр у Fidan (8 баллов = Кету ☌ Хадар 0.73° +
Сатурн ☌ Проксима 1.19° + Сатурн ☌ Толлиман 1.56°).

### R7.2 — ≥ 2 уникальных звёзд в орбе < 1° любыми не-только-узловыми планетами

```python
tight = [cj for cj in c["conjunctions"] if cj["orb"] < 1.0]
unique_stars = {cj["star"] for cj in tight}
non_node_present = any(cj["planet"] not in NODES for cj in tight)
if not only_nodes and len(unique_stars) >= 2 and non_node_present:
    return "A1_multi_personal_mid"
```

**Что ловит**: цивилизация проявлена через ≥ 2 разных канала в тугом орбе.
Планеты могут быть любого типа (личные ИЛИ внешние ИЛИ узлы), но хотя бы одна
**не узловая** — это отделяет от «чисто кармической оси Раху-Кету», которая
обрабатывается в `nodes_only` блоке отдельно.

Пример: Кит у Гульнары (Меркурий ☌ Дифда 0.36° + Марс ☌ Тау Кита 0.84° — две
личные планеты на двух разных звёздах Кита). Также сработало бы при
комбинации «1 личная + 1 внешняя» (например, Венера ☌ Антарес 0.5° + Сатурн
☌ Шаула 0.7° — обе через одну цивилизацию Скорпион).

## 4.1. Что такое R8 (правило v3.3)

R8 добавляет один системный tie-break поверх R7:

```python
if (
    group in {"B", "C", "D", "A1_low"}
    and has_personal_orb_lt_1
    and has_node_trail_same_civ_2_to_3
):
    return "A_personal_node_trail"
```

Смысл: если цивилизация уже включена точной личной планетой, а Раху или Кету
стоит в ближнем шлейфе 2°-3° той же цивилизации, это не случайная слабая
связь. Это личная линия плюс эволюционный вектор. Такая цивилизация должна
стоять выше одиночной узловой GC-точки `A_gc_wide`, но ниже точного outer,
multi-contact nodes-only и более сильных групп.

Калибровочный кейс: Лариса 26.05.1965. Орион имеет Венеру на Ригеле 0.36° и
Раху на Ригеле 2.04° как шлейф. Великий Аттрактор имеет одиночный Кету 0.76°.
После R8 Top-3 становится `Телец / Лев / Орион`, а Великий Аттрактор уходит в
узловое дополнительное влияние.

Обратная проверка на 10 старых картах: R8 сохраняет результат R7 — 30/30 по
составу, 28/30 по порядку, 10/10 set-match.

## 5. Эксперимент по выбору правила (R0 → R7)

### 5.1. Постановка

Дано: 10 клиентов с подтверждёнными эталонами Дарьи (Top-3 цивилизаций в
её ручном разборе). Baseline (v3.1, R0) даёт **8/10 совпадений по составу**
и **8/10 совпадений по порядку**. Расхождения у Гульнары и Fidan.

Задача: подобрать **системное** правило (не эвристика под конкретного клиента),
которое улучшит результат, но **не сломает** существующие 8 совпадений.

### 5.2. Тестируемые правила

| Код | Правило | Логика |
|---|---|---|
| **R0** | baseline v3.1 | без изменений |
| **R1** | ≥ 2 personal-связей T1/T2 на разных звёздах → группа `A1_multi_personal` (rank 0.5) | поднять multi-T2-personal **выше GC** |
| **R2** | weight ≥ 5.0 → `A1` | поднять «тяжёлую» цивилизацию в самый верх |
| **R3** | unique_stars ≥ 2 AND avg_orb < 1.0 → `A1` | критерий по уникальным звёздам и среднему орбу |
| **R5** | weight ≥ 4.0 → `A1` (мягче R2) | снизить порог |
| **R6** | R2 + ≥ 2 T2-personal на разных звёздах → `A1_multi_personal_mid` (rank 2.5) | R2 + R1' с пониженным рангом |
| **R7** | R2 + ≥ 2 ЛЮБЫХ-планет (не только узлы) на разных звёздах в орбе < 1° → `A1_multi_personal_mid` (rank 2.5) | **расширение R6** — любой тип планет |

### 5.3. Метрики

Для каждого клиента считаем по двум осям:

- **exact**: число позиций Top-3 кода, совпадающих с эталоном **по порядку**
  (место 1 ↔ место 1 и т.д.). Максимум 3/3 на клиента, 30/30 на всю выборку.
- **in-set**: число цивилизаций в Top-3 кода, присутствующих в эталоне
  **независимо от позиции**. Максимум 3/3 на клиента, 30/30 на всю выборку.

Агрегаты по всем 10 клиентам:

- **Сумма exact** — общее число точных позиций (0-30).
- **Сумма in-set** — общее число попаданий по составу (0-30).
- **set-match** — клиентов с полным совпадением состава (3/3 in-set, 0-10).
- **exact-match** — клиентов с полным совпадением порядка (3/3 exact, 0-10).
- **Сломал / Не сломал** — есть ли клиент, у которого in-set правила < in-set baseline.

### 5.4. Результаты эксперимента

| Правило | exact | in-set | set-match | exact-match | Сломал |
|---|---|---|---|---|---|
| **R0** | 26/30 (86.7%) | 28/30 (93.3%) | 8/10 | 8/10 | — |
| **R1** | 24/30 (80.0%) | 28/30 (93.3%) | 8/10 | 7/10 | ✗ Раиса (порядок) |
| **R2** | 26/30 (86.7%) | 29/30 (96.7%) | 9/10 | 8/10 | ✓ нет |
| **R3** | 25/30 (83.3%) | 28/30 (93.3%) | 8/10 | 7/10 | ✗ Раиса (порядок) |

| **R6** | 28/30 (93.3%) | 30/30 (100%) | 10/10 | 9/10 | ✓ нет |
| **R7** | **28/30 (93.3%)** | **30/30 (100%)** | **10/10** | **9/10** | ✓ **нет** |

### 5.6. Почему именно R7 (а не R6)

R6 и R7 дают **одинаковые метрики** на текущих 10 клиентах. Различие — широта формулы:

- **R6.2** требовал «только личные» планеты (Солнце/Луна/Меркурий/Венера/Марс).
- **R7.2** разрешает любые не-узловые планеты (личные ИЛИ внешние).

R7 шире и более универсально применимо к будущим картам. Если на новой карте
появится «1 личная + 1 внешняя» в тугом орбе на разных звёздах одной
цивилизации (например, Венера ☌ Антарес + Сатурн ☌ Шаула одного Скорпиона),
R7 поднимет её, а R6 — нет.

### 5.7. Граничные случаи R7

- **Только узлы Раху-Кету**: НЕ ловится R7.2 (требуется хотя бы одна
  не-узловая планета). Эти конфигурации обрабатываются отдельно в `nodes_only`
  блоке (направление эволюции).
- **Cosmic точки + 1 звезда**: GC ловится в `A_gc_tight` (rank 1) — выше R7.2
  (rank 2.5). Поэтому одиночные GC-связи не уступают multi-contact.
- **Одна звезда, но multiple planets**: R7.2 требует ≥ 2 **уникальных звёзд**,
  не просто 2 контактов. Это исключает дублирование (например, две планеты
  на одной звезде с разным орбом).

## 7. Протокол валидации (для будущих калибровок)

Используется при любых изменениях `tier_calculator.py`:

1. **Подготовка**: 10 эталонных клиентов с подтверждёнными Top-3
   (5 партии 1 + 5 партии 2 из `IntergalacticClientsProfiles`).
2. **Загрузка эталонов**: `reference/<slug>.md` — текстовые разборы Дарьи,
   из них вручную извлекаются Top-3 (сейчас зашиты в
   `code/simulate_tier_rules.py:DASHA_TOP` и
   `code/compare_batch2_vs_reference.py:DASHA_CANON`).
3. **Прогон**: `python3 code/simulate_tier_rules.py` или
   `python3 code/compare_batch2_vs_reference.py`.
4. **Чтение результата**: `SIMULATE_TIER_RULES.md` (если тестируются
   несколько правил) или `COMPARE_BATCH2_VS_REFERENCE.md` (если одно).
5. **Критерии приёма**:
   - in-set ≥ 90% (минимум 27/30 на 10 клиентах)
   - не ломает существующие совпадения (in-set не падает у клиентов, где
     baseline даёт 3/3)
   - набор правил остаётся системным (не ad-hoc под клиента)

### 7.1. Как добавить нового эталонного клиента

1. Получить эталон Дарьи из `IntergalacticClientsProfiles` или новой папки в
   `DariaGalacticChakra/Профайлы клиентов/Купившие разбор/<имя>_<hash>_<date>/`.
2. Скопировать markdown-разбор в `_calibration/reference/<slug>.md`.
3. Скопировать CSV в `_calibration/inputs/<slug>.csv`.
4. Извлечь Top-3 из markdown эталона (раздел «СТРУКТУРА ДНК» → «TIER-ранжирование»
   или «Топ-3 цивилизации»).
5. Добавить запись в `DASHA_TOP` (simulate_tier_rules.py) и
   `DASHA_CANON` (compare_batch2_vs_reference.py).
6. Прогнать валидацию.
