# Сопроводительное письмо: новый алгоритм подбора профессий

**Скилл:** `2-money-analysis` (ДНК денег)
**Дата:** 19.06.2026
**Кто инициировал:** Дарья

---

## Зачем это сделано (дословные указания Дарьи)

Файл профессий и новый алгоритм созданы по прямому запросу Дарьи. Её указания из чата:

1. **Запрос на пересмотр подбора:**
   > «Поясни мне, как ты сейчас подбираешь профессии исходя из всех файлов, и накидай варианты, как можно более оптимально это сделать.»

2. **Накшатра должна быть основой (раньше её не было в потоке):**
   > «Где по накшатрам профессии?»

3. **Точный алгоритм (главное указание):**
   > «Алгоритм должен быть такой: сначала накшатра — она прям определяющая для профессии, затем разветвление на то, есть ли соединение со звездой. Если да — добавляем из таблицы профессий по звёздам; если нет — пропускаем и идём просто сразу к дому. Если соединение есть — идём к дому после него. Нужно убрать знак просто, он мало информативен и мало попадает. Этот список удали из правила, но не удаляй совсем — может пригодиться. После дома уже смотришь соединения, стеллиумы и выделяешь то, что повторяется в нескольких местах — оно наиболее вероятное для человека.»

4. **Знак — в архив + жёсткое правило:**
   > «Да, убери знак в архив. Делай в задачу и потом обязательно укажи жёсткое правило по использованию.»

5. **Проверка полноты справочника:**
   > «Проверь, чтобы были все накшатры.»
   > «Мригаширу надо найти — я же сказала проверь, чтобы были все накшатры.»

---

## Что было (ДО)

- Профессии подбирались в первую очередь по связке **планета + знак зодиака** (файл `money_planet_sign_professions.md`).
- Накшатра как первичный слой **в обязательном потоке не использовалась**.
- Подбор был «ручной»: агент собирал профессии из нескольких файлов на глаз, без единого источника и без автоматизированной проверки повторов.
- Не было инструмента, который бы прогонял карту и выдавал профессии по слоям.

### Проблема
Знак мало информативен и редко попадает в цель. Подбор был непрозрачным и плохо воспроизводимым между клиентами.

---

## Что стало (ПОСЛЕ)

**Новый алгоритм (строго в этом порядке):**

```
НАКШАТРА планеты  ←  ПЕРВИЧНЫЙ определитель профессии
       ↓
Есть ☌ (соединение) со звездой/цивилизацией?
   ├─ ДА  → добавить профессии звезды (с учётом дома) → к дому
   └─ НЕТ → пропустить слой звёзд → сразу к дому
       ↓
ДОМ  ←  сфера дохода
       ↓
Соединения, стеллиумы  ←  связки планет
       ↓
ПОВТОРЫ  ←  профессии/темы у 2+ планет = НАИБОЛЕЕ ВЕРОЯТНЫЕ
```

**Новые/изменённые файлы (все внутри скилла `2-money-analysis`):**

| Файл | Что это |
|------|---------|
| `professions_master.json` | Единый справочник: **27 накшатр** + звёзды/цивилизации + 12 домов с профессиями. Источник истины. |
| `calc_professions.py` | Скрипт: читает CSV-карту → выдаёт по каждой планете накшатра → звезда (при ☌) → дом + блок ПОВТОРЫ. Перенесён из `.cursor/tools/`. |
| `money_quality_gate.md` | Жёсткое правило (секция **M**) — алгоритм + обязательный запуск скрипта. Перенесён из `.cursor/rules/`. |
| `_archive/money_planet_sign_professions.md` | Старый подбор по знаку — **в архиве**, не удалён, в обязательный поток не входит. |

**Знак убран** из обязательного алгоритма (по указанию Дарьи), сохранён в `_archive/`.

**Справочник накшатр проверен на полноту: 27 из 27.** Исправлена опечатка ключа `Мригашира` → `Мригаширша` (в CSV пишется с «ш»), из-за которой Солнце Кирилла не находило накшатру.

---

## Как пользоваться

```
python .cursor/skills/2-money-analysis/calc_professions.py "путь/к/karta.csv"
```
Вывод показать в чат. Из блока ПОВТОРЫ в первую очередь набираются 10 итоговых профессий + 1 объединяющая. Приоритет отбора: **ПОВТОРЫ > звезда (соединение) > накшатра ведущих планет**.

---

## Проверка на реальных картах

Алгоритм прогнан на картах **Кайя (12.04.1987)** и **Кирилл (20.06.1990)**: ~70% профессий из готовых разборов подтвердились повторами/соединениями. Выявлены и слепые зоны (например, у Кирилла «ресторатор» — 6 планет — в разборе не был учтён), что подтверждает ценность автоматизированной проверки.
