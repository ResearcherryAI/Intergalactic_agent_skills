# Валидация анализа миссии

## ⛔ КРИТИЧЕСКОЕ ПРАВИЛО

**Валидация = ОТДЕЛЬНЫЙ subagent через Task tool.** НЕ самопроверка автора текста. Subagent читает текст без контекста создания — это устраняет bias.

## INPUT-гейт

- [ ] `<Имя>_<DDMMYYYY>_миссия.md` существует
- [ ] `karta_*.csv` существует (для сверки)
- [ ] `summary.md` существует

## Чек-лист (проверять КАЖДЫЙ пункт)

### 1. Счётчик строк (HARD FAIL)

Подсчитать строки в `*_миссия.md`. Допустимый диапазон: **380-420 строк**.

**Fail если:** <380 или >420 строк. Это не рекомендация — это жёсткое требование.

### 2. Все важные планеты описаны

Открой CSV. Найди Раху, Кету, Плутон, Нептун, Уран. Для каждой проверь:
- Если в CSV есть строка «Соединение» → в тексте описание цивилизации
- Если соединения нет → описание через накшатру + дом

**Fail если:** хотя бы одна из 5 планет не описана.

### 3. Доминирующих цивилизаций ровно 3

Посчитай заголовки с цивилизациями. Должно быть ровно 3.
Каждая цивилизация должна содержать «Тень [имя]» — 1–2 предложения о теневой стороне.

**Fail если:** больше 3 или меньше 3, или хотя бы одна цивилизация без тени.

### 4. Профессии: раздел «Чем заняться»

- Ровно 7 направлений
- Каждое привязано к конкретным планетам/домам ЭТОГО клиента
- Нет generic-формулировок
- Раздел называется именно «Чем заняться» (не «Профессии», не «Профессиональное призвание»)

**Fail если:** <7 или >7, или шаблонные формулировки, или неправильное название раздела.

### 5. Упоминания услуг и книги

- Ровно 3 услуги: **энергодуш**, **тотальная консультация**, **сопровождение** — каждая ровно 1 раз, нативно в контексте
- Каждая услуга ОБЯЗАТЕЛЬНО оформлена как гиперссылка (markdown-ссылка на intergalactic-astrology.com)
- **РАСПРЕДЕЛЕНИЕ:** энергодуш и тотальная — в теле текста (равномерно). **Сопровождение — ТОЛЬКО в конце, прямо перед WhatsApp CTA** (завершает блок теней). Сопровождение НЕ должно быть в середине текста
- FAIL если: сопровождение стоит в середине текста (до блока теней)
- FAIL если: 2+ ссылки в одном разделе или в соседних абзацах
- FAIL если: «подробнее на сайте», «в разделе услуг», «смотрите на сайте»
- FAIL если: услуга упомянута БЕЗ гиперссылки
- FAIL если: одна услуга 2+ раз, а другая 0
- FAIL если: услуга не привязана к моменту карты
- WhatsApp CTA в конце СРАЗУ ПОСЛЕ строки с [сопровождения](url)
- ⛔ НЕТ standalone строки про книгу между *Я работаю...* и *Kaya Kaen*. Книга может упоминаться нативно в теле текста (1-2 раза), но НЕ как отдельный рекламный абзац в финале

**Fail если:** меньше 3 услуг или не названы по имени, или standalone книга в финале.

### 6. Дисклеймер

Точный текст в формате `>`:
`> Это авторский метод Кайи Каэн, проверен тысячами клиентов. Он не даёт 100% гарантии — её даст только ваш отклик и ваше Высшее Я. Помните: прямой доступ к вашей душе есть только у вас. Этот разбор — карта, по которой удобнее идти своими ногами.`

Стоит в начале клиентского текста, после вводного абзаца.

**Fail если:** отсутствует, текст изменён или стоит не в начале.

### 7. Нет дублирования (КРИТИЧНО)

- Раху не описан повторно (только в «Куда» + краткая ссылка)
- Кету не описан повторно (только в «Откуда» + краткая ссылка)
- Плутон/Нептун/Уран не описаны в двух местах полностью
- Блок материализации не дублирует блок профессий
- Каждая звезда/цивилизация описана ПОДРОБНО ровно в ОДНОМ месте

**Fail если:** одна и та же информация развёрнуто описана в двух разных местах.

### 8. Строгий фильтр связей

По CSV проверить каждую упомянутую цивилизацию/звезду:
- ☌ орб ≤1° (обычная планета) → OK
- ☌ орб ≤5° (Уран/Нептун/Плутон/Раху/Кету/Асц) → OK
- Множественные ☌ с одной цивилизацией → OK
- Аспект <0.5° как доп. информация → OK
- Что-то другое → FAIL

### 9. Материализация — 2 цивилизации

Ровно 2 цивилизации. Нет повторного абзаца о материализации.

### 10. Кету/Раху описаны правильно

- Кету С ☌ → опыт В ТОЙ ЦИВИЛИЗАЦИИ
- Кету БЕЗ ☌ → опыт НА ЗЕМЛЕ + накшатра + дом
- Раху С ☌ → эволюция через ТУ цивилизацию
- Раху БЕЗ ☌ → земные задачи + накшатра + дом + диспозитор (хозяин ЗНАКА, не накшатры!)

**Fail если:** логика перепутана или диспозитор неверный.

### 11. Терминология

- [ ] Нет «бесплатно»
- [ ] Нет «пад», «навамша»
- [ ] Нет «Млечный Путь» (правильно: «Галактический Центр», «чёрная дыра»)
- [ ] 6-й дом ≠ «кризис» (кризис = 8-й; 6-й = конфликт, трудоголизм)
- [ ] Нет «Vimshottari», «МД/АД»
- [ ] Автор = «Кайя Каэн» (НЕ «Дарья Лачинова»)

### 12. Структура и порядок блоков

**Обязательные:**
- [ ] `## 📋 СТРУКТУРА ДНК ЗВЁЗДНОЙ ДУШИ`
- [ ] `## АНАЛИЗ МИССИИ ЗВЁЗДНОЙ ДУШИ`
- [ ] Раздел Кету
- [ ] Раздел Раху
- [ ] По одному разделу на каждую из 3 цивилизаций
- [ ] `### Чем заняться` (7 профессий)
- [ ] `### Миссия одной фразой`
- [ ] Практика материализации
- [ ] `### Бонусная практика` = РОВНО 1 практика (активация/материализация через ведущую цивилизацию). ⛔ НИКАКИХ других практик (ни здоровья, ни финансов). FAIL если 2+
- [ ] `### Что может мешать реализоваться` (РОВНО 5 теней, не 4, не 6) — ПЕРЕД «Как я работаю»
- [ ] WhatsApp CTA — СРАЗУ ПОСЛЕ Теней
- [ ] *Я работаю...* — курсивом, БЕЗ ###
- [ ] Порядок финала: Тени → WhatsApp CTA → *Я работаю...* → *Разбор подготовлен...* → *Kaya Kaen*. БОЛЬШЕ НИЧЕГО (ни книги, ни ссылок, ни дополнительных абзацев)

**Запрещённые блоки:**
- [ ] НЕТ «Отношения и близость»
- [ ] НЕТ «Телесный опыт и здоровье»
- [ ] НЕТ «Ресурсы для восстановления»
- [ ] НЕТ «КАК ЧИТАТЬ КАРТУ В ЖИЗНИ»
- [ ] НЕТ «ВЗАИМОДЕЙСТВИЕ ТРЁХ ЦИВИЛИЗАЦИЙ»
- [ ] НЕТ «САКРАЛЬНЫЙ СИМВОЛ И АКТИВАЦИОННЫЕ КЛЮЧИ»
- [ ] НЕТ 📚 ИСТОЧНИКИ / 🌐 Интернет
- [ ] НЕТ HEX-кодов цветов
- [ ] НЕТ «Когда [Имя] говорит»
- [ ] НЕТ «Главная тема жизни»
- [ ] НЕТ «Дополнительные связи» / «Дополнительные линии» / «Дополнительные цивилизации»
- [ ] НЕТ «Профессиональное призвание»

### 13. Топ-3 по совокупному весу

Пересчитать по CSV: TIER 0=×3, TIER 1=×3, TIER 2=×2, TIER 3=×1.5, TIER 4=×1. При равном весе — больше соединений = выше.

**Fail если:** Топ-3 не соответствует математике.

### 14. Галактические точки

Если описаны ГЦ/Сверх-ГЦ/Аттракторы:
- Сверх-ГЦ = 33 галактики (НЕ тысячи)
- Великий Аттрактор > Сверх-ГЦ
- Практика «вертикаль» = Центавр (НЕ ГЦ)
- Если ГТ в Топ-3 выше звезды с более тугим орбом — в тексте ДОЛЖНО быть объяснение, почему (масштаб притяжения, чёрная дыра > звезда)

**Fail если:** ГТ обходит цивилизацию без объяснения в тексте.

*Источник: Влада Пискунова (01.06.1999) — ГЦ в Топ-3 выше Арктура без объяснения (pipeline_errors.md)*

### 15. Только разрешённые планеты в разделах (HARD FAIL)

В разделах цивилизаций допустимы ТОЛЬКО: **Раху, Кету, Плутон, Нептун, Уран, Асцендент**.

Сканировать текст: если Марс, Меркурий, Венера, Юпитер или Сатурн описаны как отдельная подтема внутри раздела цивилизации (не краткое упоминание, а развёрнутый абзац) — FAIL.

**Fail если:** запрещённая планета имеет собственный подраздел или развёрнутое описание внутри цивилизации.

*Источник: Юлия (11.04.1983) — Марс и Меркурий в разделах; Анастасия Федорова (21.03.1979) — все планеты вместо миссионных (pipeline_errors.md)*

### 16. Город и имя совпадают с CSV и папкой (HARD FAIL)

1. Открыть CSV → строка `# Город;` → сверить с городом в тексте MD
2. Имя из названия папки клиента → сверить с именем в MD (заголовок, обращения)
3. Открыть `summary.md` → сверить имя и город с миссия.md

**Fail если:** город в тексте ≠ город в CSV, или имя в MD ≠ имя из папки, или summary.md содержит другое имя/город.

*Источник: Лили (31.01.1980) — имя «Юлия» вместо «Лили», город «Одесса» вместо «Ташкент» (pipeline_errors.md)*

### 17. Нет практик цивилизаций (кроме бонусной)

Практики цивилизаций (медитации, ритуалы, «практика связи с...») — дополнительная платная услуга. В разборе допустима ТОЛЬКО бонусная практика материализации в конце.

Сканировать текст: если найдены развёрнутые практики (>3 шагов) привязанные к конкретной цивилизации — FAIL.

**Fail если:** в тексте есть практики цивилизаций помимо бонусной материализации.

*Источник: Анастасия Федорова (21.03.1979) — включены практики из книги (pipeline_errors.md)*

### 18. Доп. влияния — орб ≤1.00° (HARD FAIL)

Если в тексте есть строка/блок «Дополнительные влияния» или аналог — проверить по CSV: каждое упомянутое соединение должно иметь орб ≤1.00°.

Исключение: Уран, Нептун, Плутон — допустимы с орбом до 5°.

**Fail если:** в доп. влияниях присутствуют соединения с орбом >1.00° (кроме Уран/Нептун/Плутон).

*Источник: Екатерина (13.05.1994) — Великий Аттрактор (Asc 2.0°), Капелла (Венера 1.5°) в доп. влияниях (pipeline_errors.md)*

### 18b. Все аспекты ВЕРИФИЦИРОВАНЫ по CSV (HARD FAIL)

Каждый аспект, упомянутый в тексте (секстиль, трин, квадрат, оппозиция), ОБЯЗАН присутствовать в CSV-файле клиента. Проверка:
- [ ] Планета совпадает
- [ ] Тип аспекта совпадает (секстиль/трин/квадрат/оппозиция)
- [ ] Звезда совпадает
- [ ] Орб ≤ отклонение 0.1° от CSV

**HARD FAIL если:** хотя бы один аспект в тексте ОТСУТСТВУЕТ в CSV. Это означает, что аспект выдуман. Подрывает доверие ко всему разбору.

**⚙️ ОБЯЗАТЕЛЬНЫЙ ПРОГОН СКРИПТА (до генерации PDF):**
```
python .cursor/skills/3-validation/verify_aspects.py "<путь_к_папке_клиента>"
```
Exit code 0 = OK. Exit code 1 = HARD FAIL, отправка запрещена.
Скрипт парсит MD, извлекает все аспекты (секстиль/трин/квадрат/оппозиция), сверяет каждый с CSV по планете + типу + звезде + орбу. Несоответствия выводятся в stdout.

*Источник: Елена (27.06.1963) — Поллукс и Алголь не существуют в CSV, орб Сверх-ГЦ подменён (3.07° → 0.42°)*

### 19. Аттрактор Шепли ≠ отдельная цивилизация при наличии Плутона

Если Плутон в соединении с Аттрактором Шепли — АШ описывается ВНУТРИ блока Плутона. Нельзя выносить АШ как отдельный раздел «четвёртая цивилизация», если Плутон уже описывает ту же точку → задвоение.

**Fail если:** АШ расписан как отдельная цивилизация И Плутон тоже описывает АШ в своём блоке.

*Источник: Ирина (03.06.1985) — задвоен Плутон, АШ и Плутон описывали одно и то же (pipeline_errors.md)*

### 20. Нет дублей абзацев (посимвольный поиск)

Сканировать текст на повторение целых абзацев или предложений длиной >50 символов. Особое внимание: блок материализации не должен дублировать блок профессий.

**Fail если:** найдены два абзаца с совпадением >80% текста.

*Источник: Мария Козак (06.08.1996) — задвоено упоминание материализации (pipeline_errors.md)*

### 21. Пол и местоимения (HARD FAIL)

Определить пол клиента по имени (русские: -а/-я/-ья = ж, согласная/й = м; иностранные: типичные паттерны; default = ж). Сканировать текст:
- `gender: м` → НЕ должно быть «она», «её» (притяжательное женское), «женщина» в описаниях клиента
- `gender: ж` → НЕ должно быть «он», «его» (притяжательное мужское), «мужчина» в описаниях клиента
- Нейтральное «человек» вместо гендерного обращения = FAIL

**Fail если:** местоимения не соответствуют полу клиента, или используется «человек» вместо «мужчина»/«женщина».

*Источник: Гастон (17.10.1983) — текст использовал «человек» вместо «мужчина» (pipeline_errors.md)*

### 22. Нет служебных предупреждений в тексте (HARD FAIL)

Сканировать текст на наличие:
- «⚠️» в любом контексте
- «часовой пояс», «часовых поясов СССР», «расхождение», «рекомендуется сверить»
- «source_check», «чанк», «саммари», «library_compact», «build_index»
- «проверить», «уточнить расчёт», «возможно расхождение»
- Любые технические пометки, адресованные Дарье, а не клиенту

**Fail если:** найдено хотя бы одно служебное предупреждение или техническая пометка.

*Источник: Елена (10.03.1982) — в тексте стояло «⚠️ Дата рождения приходится на советский период…» (pipeline_errors.md)*

### 23. summary.md — контракт парсера

Проверить `summary.md`:
- Первый символ = `---` (frontmatter)
- Обязательные поля: `civilization` и `headline` (headline ≤120 символов)
- Ровно 3 секции `## …` после frontmatter
- Каждая секция имеет ≥1 пункт `- текст`
- Пустая секция = FAIL
- Имя клиента НЕ упоминается в буллетах
- Тон: «вы», без эзотерических штампов

**Fail если:** frontmatter невалиден, секций ≠ 3, есть пустые секции, headline >120 символов.

## 🆕 ПОРЯДОК ВАЛИДАЦИИ AI-РАЗБОРОВ (новый, с 22.05.2026)

**Ключевой принцип:** бенчмаркинг идёт **ПЕРВЫМ — для RAW файла от агента**. Это позволяет:
1. Объективно оценить, как сработал AI-агент (вход для доработки промпта n8n)
2. Передать валидатору не только текст, но и **конкретные fail-коды** — валидация становится точнее
3. Сравнить «до/после» доработки Кайи (если она вообще понадобится)

### Шаг 1: Бенчмарк RAW (от агента, ДО любых правок)

```powershell
python .cursor/skills/3-validation/benchmark.py "<raw_миссия.md>" "Топ1,Топ2,Топ3" --json
```

Второй аргумент — ожидаемый Топ-3 (через запятую) из ручного расчёта по CSV (TIER-логика из `2-analysis`).

**Output:** JSON `{score, passed, total, fails, stats}`. Exit code 0 если score ≥ 0.90, иначе 1.

### Шаг 2: Verify aspects RAW

```powershell
python .cursor/skills/3-validation/verify_aspects.py "<папка_клиента>"
```

Проверка: каждый аспект (секстиль/трин/квадрат/оппозиция) в RAW реально есть в CSV. Exit code 1 = выдуманные аспекты в RAW = серьёзный сигнал для промпта агента.

### Шаг 3: Создание `benchmark_report.md` (секция «raw / агент»)

В папке клиента создаётся отчёт **сразу после шагов 1-2**, ещё ДО валидации и любых правок:

```markdown
# benchmark_report

## Секция 1: RAW от AI-агента (что сделал n8n→Anthropic)

| Метрика | Значение |
|---|---|
| Score | 0.7741 (24/31) |
| Длина | 392 строк |
| Книга упомянута | 1 раз |
| Аспекты вне CSV | 2 (Поллукс, Алголь) |
| Решение оркестратора | требуется доработка (score < 0.90) |

### Fails в RAW:
- D1_pro_count_5: 5 профессий вместо 7
- D4_teni_count_6: 6 теней вместо 5
- E7_extra_practices_2: 2 лишние практики (активация Дракона, утренний огонь)
- B3_book_2plus: книга упомянута 1 раз (нужно ≥2)
- 18b_aspect_not_in_csv: Поллукс не существует в CSV
```

Этот отчёт — **input для шага 4 (валидация)** и для Дарьи (оценка агента).

### Шаг 4: Валидация RAW по чек-листу (subagent)

Subagent читает RAW + benchmark_report (секция raw) + CSV и проверяет смысловые пункты, которые бенчмарк не ловит:
- Топ-3 соответствует TIER-логике (не только формально совпадает по составу)
- Тон обращения «вы», без «она/он»
- Дисклеймер на месте СРАЗУ после вводного абзаца
- Город/имя соответствуют CSV и Sheet
- Гендер местоимений корректен
- Услуги нативно вписаны, не «подробнее на сайте»
- Книга упомянута через гиперссылку (если упомянута)
